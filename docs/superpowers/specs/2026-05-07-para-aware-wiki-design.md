# PARA-Aware Wiki Architecture

**Date:** 2026-05-07
**Status:** Approved
**Scope:** Refactor brain-wiki extension to integrate with PARA vault structure

## Problem

The wiki is currently a sandbox disconnected from the real vault. Wiki topics are hollow stubs. The agent captures sources but doesn't participate in the PARA workflow. The boundary between agent-owned and human-owned zones is unclear.

## Design Approach

**Wiki as Living Index** — Wiki becomes a navigational layer over the PARA vault. Agent maintains topic pages that map the vault structure and synthesize captured knowledge. Three new tools connect the agent to PARA zones.

## Zone Map

| Zone | Path | Agent | Human |
|------|------|-------|-------|
| **Human-only** | `Area/` | Read only | Full control |
| **Agent-writable** | `Resource/`, `Draft/` | Can create/edit | Full control |
| **Shared** | `LIST.md`, `Project/` | Can read/write | Full control |
| **Wiki (agent-owned)** | `Wiki/` | Full control | Read/browse |
| **Protected** | `Wiki/inbox/`, `Wiki/meta/` | Auto-generated | No touch |

**Key rule:** Agent can read everything, write only in its zones. Area/ is sacred — agent never modifies it.

## Wiki as Living Index

Wiki topic pages are structured indexes over the PARA vault. Two layers of content:

### Layer 1: PARA skeleton (auto-generated by `wiki_sync`)

Scans vault folders, generates topic structure:
- Each `Area/` shelf → topic page (e.g., `topics/self-and-career.md` maps to `Area/0 Me/`)
- Each `Resource/` JD box → topic page (e.g., `topics/computer-science.md` maps to `Resource/1 CS/`)
- Active `Project/` folders → plan pages (e.g., `plans/sales-tool-poc.md`)

Topic page structure:
```markdown
---
type: topic
title: Computer Science
source: Resource/1 CS/
status: active
---

# Computer Science

## Vault Map
- [[Resource/1 CS/10 Reading/]] — CS reading notes
- [[Resource/1 CS/11 Programming Language/]] — language theory
- [[Resource/1 CS/17 AI/]] — ML, LLMs, neural nets

## Synthesis (enriched from sources)
- Key concepts the agent has learned from captured sources
- Links to summary pages: [[summaries/...]]

## Open questions
- What the agent noticed but can't resolve
```

### Layer 2: Source synthesis (existing capture flow)

Agent captures sources into `inbox/`, creates summaries, then enriches topic pages with what it learned. This is the bottom-up layer.

**Result:** Topics are both a map of your vault AND a synthesis of external knowledge. They answer: "What's in this area?" and "What has the agent learned about it?"

## LIST.md Integration

`LIST.md` is the shared routing center between human and agent.

### Agent permissions
- Read LIST.md to understand current priorities and context
- Add items (from captured sources, project updates, reminders)
- Suggest project links (e.g., "this task relates to [[Project/Sales Tool]]")
- Flag stale items (unchecked items older than 7 days)

### Agent restrictions
- Cannot mark items complete
- Cannot delete items
- Cannot reorder or restructure the file

### AI content rule
All agent-generated content in LIST.md must be inside a blockquote with an AI indicator:
```markdown
> 🤖 [AI] Agent note: This task relates to [[summaries/2026-05-07-ai-coding-tools]]
```

This keeps human and agent content visually distinct.

## Project/ Integration

Agent can read and write in `Project/` folders.

### Agent permissions
- Read project folders to understand active work
- Add research notes from captured sources
- Update task lists (add items, mark progress)
- Create project plan pages in `Wiki/plans/`

### Agent restrictions
- Cannot create new project folders (human decides what becomes a project)
- Cannot delete or archive projects
- Cannot change project structure or status

## Write Gate Changes

Update the guard logic to enforce the new zone map:

### Blocked (hard block)
- `Area/**` — never touched by agent
- `Wiki/inbox/**` — immutable source packets
- `Wiki/meta/**` — auto-generated metadata

### Allowed (agent-writable)
- `Resource/**` — raw knowledge filing
- `Draft/**` — staging area
- `Project/**` — shared work space
- `LIST.md` — shared routing center
- `Wiki/**` (except inbox/meta) — agent's index layer

### Config
```json
{
  "protect": [
    "Area/**",
    "Wiki/inbox/**",
    "Wiki/meta/registry.json",
    "Wiki/meta/backlinks.json",
    "Wiki/meta/events.jsonl",
    "Wiki/meta/index.md",
    "Wiki/meta/log.md",
    "Wiki/meta/lint-report.md"
  ],
  "allowExternal": [
    "../LIST.md",
    "../Project/**",
    "../Resource/**",
    "../Draft/**"
  ]
}
```

Guard logic:
1. Is path in `protect`? → Block
2. Is path in wiki root? → Allow (wiki zone)
3. Is path in `allowExternal`? → Allow
4. Otherwise → Block

## New Tools

### `wiki_sync`

Scans PARA vault structure and updates wiki topic pages.

**Parameters:**
- `scope`: `"area" | "resource" | "projects" | "all"`

**Returns:**
- `{ topicsCreated: number, topicsUpdated: number, pages: string[] }`

**Behavior:**
- Scans `Area/` folders → creates/updates topic pages with vault map
- Scans `Resource/` JD shelves → creates/updates topic pages with box listings
- Scans `Project/` folders → creates/updates plan pages in wiki
- Preserves existing synthesis content in topics (Layer 2)

### `wiki_triage`

Manages LIST.md as shared routing center.

**Parameters:**
- `action`: `"read" | "add" | "suggest" | "flag_stale"`
- `content?`: string (for add action)

**Returns:**
- `{ analysis?, added?, suggestions?: string[] }`

**Behavior:**
- `read` — parse LIST.md, return current items grouped by age/status
- `add` — append a new item with `> 🤖 [AI]` prefix
- `suggest` — analyze captured sources, suggest related LIST.md items
- `flag_stale` — find unchecked items older than 7 days

### `wiki_project_sync`

Syncs with Project/ folders.

**Parameters:**
- `action`: `"scan" | "add_note" | "suggest_task"`
- `project?`: string
- `content?`: string

**Returns:**
- `{ projects?, noteAdded?, taskSuggested? }`

**Behavior:**
- `scan` — list all Project/ folders with status and recent activity
- `add_note` — append research note to a project folder
- `suggest_task` — add task suggestion to LIST.md with AI indicator

## Obsidian CLI Rule

Any operation that the Obsidian CLI supports must go through it (move, rename, create, read). Direct filesystem access only for operations the CLI doesn't handle. This preserves wikilinks automatically.

The existing `ObsidianClient` will be extended to support the new tools.

|------|-------|-------------|

| Resource/ | Agent | File captured sources |
| Wiki/ | Agent | Maintain knowledge graph index |
| Area/ | Human | Read only — never touches |
